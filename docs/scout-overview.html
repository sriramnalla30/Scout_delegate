How Scout works, on one page

Scout finds real places on Google Maps from a chat message (“gyms in Koramangala Bangalore”, “yoga near me”). Two AI agents talk and decide; plain code and two tools do the work. Read the picture from the top down, in the order of the numbers.

AI agent: a model decides plain code: no model tool: does the real work saved on disk a request goes down an answer comes up a tool call and its result pause and ask the person

The steps

  1. You send a message. The page posts it to the API (POST /api/chat).
  2. The API runs one turn of the Coordinator, an AI agent that only talks to the person.
  3. The Coordinator calls the Scout with the request and every answer you gave so far.
  4. The Scout, a second AI agent, works out the kind of place, the area and the city. It calls geocode for a pin, then search_places for the places.
  5. search_places saves every place to disk under an id. Only the count and the best three go back to the AI.
  6. The Scout returns a status, which code checks. The Coordinator turns it into a short reply.
  7. The page asks the API for the full results by id and draws one card per place.

Something missing? The Coordinator calls ask_user (a question in words) or ask_browser (your position, for “near me”). The run pauses. Your answer resumes the same run.

What the Scout can answer

ready

Places were found. The Coordinator says how many and names the best one.

needs_input

A detail is missing, or the search found nothing. The Coordinator asks you (at most 3 times).

failed

A tool broke. The Coordinator says what went wrong in one sentence.

Three rules to remember

The models never read the full results.

They get the count and the best three. The full list lives on disk, by id; only the page loads it.

Code checks the AI.

A “ready” answer is kept only if a search really ran with a real pin (finalize and complete in app/scout_agent.py).

“Near me” keeps your position away from the models.

The server holds it in memory (app/location.py). The AI sees only “DEVICE LOCATION: available” or “not available”.

Every branch in detail (near me, missing details, no results, tool errors, the 3-question limit) is in scout-flow.html. File map and run steps are in the README.
